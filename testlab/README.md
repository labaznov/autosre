# Тестовая лаборатория

Стенд, на котором агента можно запустить по-настоящему: VictoriaLogs,
VictoriaMetrics и генератор потока, похожего на прод. Нужна затем, что
поддельный источник в тестах проверяет разбор ответа, а лаборатория —
поведение: сходится ли ряд, находится ли всплеск, не тонет ли дежурный в шуме.

## Как поднять

```bash
cd testlab
make up       # логи, метрики, генератор
make agent    # агент поверх них
make watch    # что пишет генератор
```

Данные видно глазами: логи — `http://127.0.0.1:9428/select/vmui`, метрики —
`http://127.0.0.1:8428/vmui`, агент — `http://127.0.0.1:8096/api/health`.

Веб-морда агента — `http://127.0.0.1:8096/`, вход `duty` / `autosre-lab`.
Пароль лаборатории записан открыто намеренно: прятать его тут не от кого.

`make knowledge` заводит рабочую копию репозитория знаний из
[`examples/knowledge`](../examples/knowledge/) и кладёт её под git. Агент пишет
туда черновики и отчёты, а приёмка черновика делает настоящий коммит — образец
в `examples` при этом остаётся нетронутым.

`make clean` останавливает всё и стирает тома.

## Что генерируется

Шесть сервисов с разной болтливостью и разной обычной долей ошибок. Фон ровный:
`zabbix-proxy` шумит всегда, `victorialogs` в норме молчит — этой разницы
достаточно, чтобы проверить, что пороги не одни на всех.

**История засевается при старте** — по умолчанию шесть часов назад
(`SEED_HOURS`). Без базовой линии детектору не с чем сравнивать, а ждать шесть
часов на каждом запуске лаборатории незачем.

### Сценарии

| Что | Где | Когда |
| :--- | :--- | :--- |
| Всплеск: треть строк сервиса становится ошибками (42 в минуту против фонового одного) | `orders-api`, `litellm`, `victorialogs` по очереди | каждые полчаса, четыре минуты |
| Ползучая утечка памяти | `llama-server` | всё время, ~0,9 МБ в минуту |
| Заполняющийся диск | `/data` | всё время, ~3 МБ в минуту |

Всплеск виден на пятнадцатиминутном горизонте; утечка и диск — только на
часовом, потому что ни в одном коротком окне скачка нет. Это и есть проверка
того, ради чего горизонты разведены по вопросам.

Расписание жёсткое, зерно случайности задано (`RANDOM_SEED`) — прогон
повторяется. Если поведение агента меняется от запуска к запуску при том же
зерне, дело в агенте, а не в данных.

## Что посмотреть

```bash
make errors    # сколько ошибок по сервисам за час — глазами, мимо агента
make buckets   # что агент успел снять
```

Полезно сравнивать: если `make errors` показывает всплеск, а у агента ряд
стоит — виноват съём, а не детектор.

## Проверено на живой лаборатории

17.08.2026: шесть часов истории — 109 810 строк; всплеск `orders-api` 42 ошибки в
минуту четыре минуты подряд против фонового одного; память `llama-server`
457 → 564 МБ за два часа; свободное место на `/data` убывает.

Агент за ту же минуту снял ровно те же числа, что показывает запрос к
`VictoriaLogs` глазами, — сверено потоком в потоко́м.

## Модель

Живого инференса здесь нет: лаборатория проверяет конвейер, а не качество
разбора. Вместо `LiteLLM` поднимается поддельный OpenAI-совместимый сервер с
предсказуемым правилом отсева — первое появление сигнатуры проходит дальше,
повторы гасятся как привычный шум. Ровно то поведение, ради которого отсев и
заведён, и прогон от этого остаётся повторяемым.
