# Репозиторий знаний: устройство и форматы

Знания, скиллы и отчёты живут в отдельном репозитории —
[ADR-0015](adr/0015-knowledge-repository.md). Здесь описано, как он устроен и
в какой форме там всё лежит. Рабочий образец — в [`examples/knowledge/`](../examples/knowledge/).

Документ описывает **интерфейс между людьми и агентом**. Менять его дороже, чем
менять код: файлы уже написаны людьми и лежат в чужом репозитории.

## 1. Структура

```
skills/    скиллы анализа — что и как смотреть
notes/     принятые заметки — известные ошибки, разборы аварий, приёмы
drafts/    черновики агента, ждущие приёмки дежурным
reports/   отчёты: по инцидентам, по горизонтам, недельные
```

Кто во что пишет:

| Каталог | Люди | Агент |
| :--- | :---: | :--- |
| `skills/` | пишут и правят | только читает |
| `notes/` | пишут и правят, принимают черновики | только читает |
| `drafts/` | правят и переносят в `notes/` | создаёт новые файлы |
| `reports/` | читают | создаёт новые файлы |

Агент **создаёт файлы, но не изменяет чужие**. На этом инварианте держится
отсутствие конфликтов слияния: перед коммитом достаточно `pull`.

## 2. Скилл

Markdown с фронтматтером ([ADR-0003](adr/0003-skills-as-markdown.md)).
Фронтматтер — машинная часть, тело — инструкция модели на русском.

### Поля фронтматтера

| Поле | Обяз. | Значение |
| :--- | :---: | :--- |
| `name` | да | идентификатор: латиница, kebab-case, совпадает с именем файла |
| `title` | да | человеческое название, по-русски |
| `horizon` | да | `5m`, `15m`, `1h`, `24h` — на каком горизонте применяется |
| `when` | да | условие применения, см. ниже |
| `collect` | да | запросы первого досье |
| `tools` | нет | что разрешено добирать: `logs`, `metrics`, `knowledge`. По умолчанию всё |
| `steps` | нет | предел шагов добора, по умолчанию берётся из настроек агента |

### `when` — когда скилл применяется

```yaml
when:
  signal: errors        # errors | metric — по какому сигналу пришло отклонение
  stream: '.*'          # необязательно: regexp по селектору потока
  metric: 'process_.*'  # необязательно: regexp по имени метрики
```

Скилл применяется, если совпали **все** заданные условия. Если подходят
несколько скиллов, работают все — каждый даёт своё досье и свой разбор.

### `collect` — первое досье

```yaml
collect:
  - id: signatures       # имя, под которым результат придёт в промпт
    vl: '...'            # запрос на языке источника: vl — LogsQL, vm — PromQL
    limit: 200           # необязательно, предел строк
```

Подстановки в запросах:

| Подстановка | Чем заменяется |
| :--- | :--- |
| `{start}` `{end}` | границы окна горизонта, RFC 3339 |
| `{horizon}` | ширина окна словом: `15m`, `1h` |
| `{stream}` | селектор потока, по которому пришло отклонение |
| `{service}` | имя сервиса, вытащенное из селектора |

Подстановка — единственный способ попасть в запрос данным из наблюдения.
Собирает запрос агент, в одном месте, с экранированием.

### Тело

Свободный текст по-русски: на что смотреть, как отличить одно от другого, что
считать нормой. Тело уходит в промпт как есть, поэтому длина тела — это бюджет
токенов. Ориентир: до 15 строк.

### Совместимость

Скиллы живут дольше версий агента. Незнакомое поле фронтматтера — строка
предупреждения в журнале, а не отказ загрузки. Отсутствие обязательного поля —
отказ этого скилла, но не падение агента.

## 3. Заметка

Единица базы знаний. Три вида, отличаются полем `kind`:

| `kind` | О чём | Главное в теле |
| :--- | :--- | :--- |
| `error` | известная ошибка | сигнатура → что значит → что делать |
| `incident` | разобранная авария | что было, причина, как чинили |
| `method` | приём диагностики | как смотреть, чем мерить |

```yaml
---
name: vl-no-space-left
title: Кончилось место на диске под данные
kind: error
tags: [диск, victorialogs, no-space-left]
signatures:
  - 'no space left on device'
  - 'ENOSPC'
services: ['victorialogs']
---
```

| Поле | Обяз. | Значение |
| :--- | :---: | :--- |
| `name` | да | идентификатор, совпадает с именем файла |
| `title` | да | человеческое название |
| `kind` | да | `error`, `incident`, `method` |
| `tags` | да | слова для поиска, в том числе синонимы на русском |
| `signatures` | нет | точные куски сообщений — по ним заметка находится вернее всего |
| `services` | нет | к каким сервисам относится |
| `related` | нет | имена связанных заметок |

Поиск идёт по телу, тегам и сигнатурам
([ADR-0008](adr/0008-full-text-knowledge-search.md)). Поэтому **теги обязаны
содержать русские синонимы**: «диск кончился» сам по себе не найдёт
`no space left`.

## 4. Черновик

Заметка, написанная агентом. Отличается местом (`drafts/`) и тремя полями:

```yaml
author: agent
incident: 1043        # из какого инцидента родился
confidence: 0.4       # насколько агент сам себе верит
```

Имя файла: `ГГГГ-ММ-ДД-краткое-имя.md`.

Приёмка — перенос файла в `notes/` с удалением этих трёх полей и правкой текста
([ADR-0009](adr/0009-drafts-before-knowledge.md)). Кто принял и что поправил,
видно в истории git.

## 5. Отчёт

Создаётся агентом, людьми не правится.

```
reports/incidents/2026-08-14-1043-orders-api.md
reports/daily/2026-08-14.md
reports/weekly/2026-W33.md
```

Фронтматтер: `kind` (`incident`, `daily`, `weekly`), `period` или `incident`,
`created`. Тело — markdown для человека.

## 6. Правила

**Имена файлов — латиницей**, содержимое — по-русски. Имя файла попадает в
ссылки и в журналы, где кириллица только мешает.

**Одна заметка — одна мысль.** Заметка, в которой три разные ошибки, не найдётся
ни по одной из них.

**Ссылка вместо копии.** Повторяющийся кусок выносится в отдельную заметку и
упоминается в `related`.
