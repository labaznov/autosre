# План

Срез — узкая, но сквозная цепочка: от источника до наблюдаемого результата.
Первый и второй закрыты, третий в работе. Разбивка на задачи — [`TASKS.md`](TASKS.md).

## Первый срез

Решение сессии 5: работает **весь конвейер на одном горизонте**. Узкая, но
сквозная цепочка — от бакета в источнике до карточки на экране.

Смысл выбора: сквозной срез проверяет то, что нельзя проверить по частям, —
что цепочка сходится и укладывается в бюджет времени. Слой за слоем строить
дешевле, но правда о времени до вывода выясняется только целиком.

### Что входит

| Часть | Объём |
| :--- | :--- |
| Коннектор логов | снятие минутных бакетов, выборка строк, исключение своих потоков |
| Коннектор метрик | снятие минутных бакетов по правилам отбора |
| Ряд наблюдений | накопление в SQLite, дозапрос дыр при старте, свёртка |
| Детектор | горизонт 15 минут, робастный порог, два правила: события и уровень |
| Отсев | короткий промпт со схемой ответа |
| Очередь | вес, потолок одновременных, отступление к голым числам |
| Расследование | один скилл, ограниченный добор, вывод модели |
| Инцидент | узкая группировка, открытие и закрытие, метка связи |
| Веб-морда | вход, лента, карточка, оценка инцидента |
| Обвязка | конфигурация TOML, свои метрики наружу, роль Ansible |

### Что не входит

Отложено сознательно, каждое — отдельным срезом после:

- база знаний: поиск похожего и черновики;
- заявки на диагностику;
- отчёты всех видов;
- приглушение;
- объединение и разделение инцидентов;
- горизонты «час» и «сутки»;
- второй и третий скиллы.

Пятиминутный горизонт не входит и по умолчанию выключен
([ADR-0014](adr/0014-horizons-are-configurable.md)).

### Порядок

Каждый шаг оставляет систему в рабочем состоянии, и каждый следующий опирается
на предыдущий.

1. **Ряд наблюдений.** Коннектор логов, минутные бакеты, накопление, дозапрос
   дыр. Проверяется на живых данных пилота: ряд заполняется и переживает
   перезапуск.
2. **Детектор.** Отклонения по логам на горизонте 15 минут. Смотрим глазами,
   что находится, и калибруем пороги.
3. **Метрики.** Второй коннектор, правила отбора, второе правило детекции. Это
   же проверка границы трейта: если она удобна, второй коннектор ложится без
   правок первого.
4. **Инцидент и лента.** Группировка, жизненный цикл, веб-морда со входом.
   С этого шага система полезна дежурному без всякой модели.
5. **Отсев.** Первый контур модели. Считаем, сколько отклонений он гасит.
6. **Расследование.** Скилл, добор, вывод. Замеряем время до вывода и долю
   подозрений, дошедших без него.

Шаги 1–4 не трогают инференс вовсе. Это не случайность: к моменту, когда
подключается модель, детектор уже откалиброван на живых данных, и качество
вывода не путается с шумом детекции.

### Что сделано

Шаги 1–6 закрыты, кроме развёртывания на стенд и калибровки: и то и другое
требует доступа, которого у исполнителя нет. Сквозной прогон на лаборатории
прошёл целиком — от пустой базы до вывода на карточке за три минуты.

### Когда срез считается готовым

- ряд наблюдений не имеет дыр после суток работы, включая перезапуск;
- отклонения находятся и объяснимы числами;
- время до обнаружения на живых данных — 5 минут по 90-му процентилю;
- время до вывода — 15 минут по 90-му процентилю;
- дежурный видит ленту и карточку и может оценить инцидент;
- ни один шаг не требует ручного вмешательства после развёртывания.

## Второй срез

Первый срез сделал агента **видящим**: он замечает, разбирает и показывает.
Второй делает его **помнящим и разговаривающим**: он спрашивает дежурного,
когда данных не хватает, накапливает знание о своём хозяйстве и отчитывается.

Смысл выбора: после первого среза каждый инцидент разбирается с чистого листа.
Агент не помнит вчерашнего, не может задать вопрос и не умеет рассказать, что
происходило за сутки. Это три разные дыры, но у них одна причина — замкнутость
на себе. Второй срез её и вскрывает.

### Что входит

| Часть | Объём |
| :--- | :--- |
| Заявка | вопрос дежурному, ответ в карточке, продолжение расследования |
| База знаний | чтение заметок, полнотекстовый поиск, индекс |
| Похожий случай | заметки в досье расследования, видно, по каким словам нашлись |
| Черновик | агент пишет заметку, дежурный принимает кнопкой |
| Приглушение | пара «сервис плюс сигнатура» замолкает на срок |
| Правка группировки | объединение и разделение инцидентов |
| Отчёты | по инциденту, суточный, недельный |

### Что не входит

- отправка отчётов в мессенджеры — формат к ней готов, канал отдельно;
- векторный поиск по знаниям ([ADR-0008](adr/0008-full-text-knowledge-search.md)
  оставляет его вторым источником кандидатов на потом);
- модель доступов сложнее пары «логин плюс пароль»
  ([ADR-0020](adr/0020-login-and-password.md));
- SSH на хосты: заявка — это и есть решение
  ([ADR-0011](adr/0011-diagnostic-requests.md)).

### Порядок

1. **Заявка.** Расследование получает право спросить. Замыкает петлю, которую
   первый срез оставил открытой: непонятное некуда было девать.
2. **Знание.** Чтение базы, поиск, похожий случай в досье, черновики. Отсюда
   агент перестаёт начинать каждый раз с нуля.
3. **Шум.** Приглушение и правка группировки — то, чем дежурный чинит ошибки
   агента, не трогая настроек.
4. **Отчёты.** По инциденту, суточный, недельный. Собираются из накопленного,
   поэтому идут последними.

### Что сделано

Задачи 15–24 закрыты. Сквозной прогон на лаборатории прошёл: агент читает базу
знаний, оставляет заявки, пишет черновики и собирает отчёты. Осталось то же,
что и после первого среза, — развёртывание на стенд и калибровка на живых
данных.

### Когда срез считается готовым

- расследование, упёршееся в нехватку данных, оставляет заявку, а не сдаётся;
- ответ дежурного возвращает инцидент в очередь и попадает в вывод;
- заметка из базы знаний влияет на вывод, и видно, какая именно;
- принятый черновик появляется в репозитории знаний коммитом;
- приглушённое не пропадает, а видно в суточном отчёте строкой
  «приглушено, но продолжается»;
- суточный отчёт собирается сам и содержит все четыре части;
- дежурный может исправить любую ошибку группировки, не трогая базу руками.

## Третий срез

Первые два среза сделали агента видящим, помнящим и разговаривающим. Третий
делает его **честным и переносимым**: всё, что обещано в документах, делается
кодом, а сам агент ставится одним файлом на сервер без интернета.

Смысл выбора: ревизия ([`REVIEW.md`](REVIEW.md)) нашла обещания без кода —
запросы скиллов, сроки хранения, здоровье, дозапрос — и деплой, который
требует Docker, Ansible и сети до crates.io на проде. Для одного
сопровождающего это два главных риска, и оба не про новые возможности.

### Что входит

| Часть | Объём |
| :--- | :--- |
| Корпус живых данных | уже сделан вне списка задач ([ADR-0027](adr/0027-live-corpus.md)) |
| Запросы скиллов | `Source::query`, подстановки, исполнение `collect` |
| Горизонт инцидента | столбец вместо разбора сигнатуры |
| Сроки хранения | все таблицы, а не только ряды |
| Живучесть | периодический дозапрос, повторные попытки, здоровье с содержанием |
| Порядок | мёртвая конфигурация, словарь, состояния |
| Бандл | статический бинарь, systemd, `install.sh`, сборка на тег |
| Команды | `check`, `--version`, `backup` |
| TLS | встроенный, самоподписанный по умолчанию |

### Что не входит

- сезонная базовая линия и подбор порогов — после первой живой недели;
- приоритет сервиса, webhook, классификатор отсева — четвёртый срез;
- комплект модели: стенд остаётся, агент ходит по адресу.

### Порядок

1. **Честность.** Задачи 26–30: сначала код догоняет документы. Бандл, собранный
   раньше, унёс бы на сервер известные дыры.
2. **Бандл.** Задачи 31–34: упаковка, команды первого дня, TLS, удаление роли.

### Что сделано

Задачи 25–34 закрыты. Установка из тарбола проверена на чистом Debian с
заглушкой `systemctl`, HTTPS — на живом бинаре. Не проверено: запуск под
настоящим systemd и живые данные — и то и другое требует сервера.

### Когда срез считается готовым

- каждый запрос из `collect` скилла исполняется и его результат виден в досье;
- скилл для логов на горизонте суток применяется;
- ни одна таблица не растёт без предела;
- час простоя источника закрывается дозапросом без перезапуска;
- `/api/health` отвечает 503, когда ряд отстал;
- тарбол ставится на чистую виртуалку без сети по инструкции на одну страницу;
- `autosre check` до старта называет каждую недоступную службу.
