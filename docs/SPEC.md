# Спецификация: агент диагностики

Статус: черновик. Ведётся до кода и правится раньше кода — если поведение
разошлось со спекой, неправ код.

Версия 0.1 · заведена 14.08.2026

---

## 1. Задача

Второй контур наблюдения за прод-системой. Агент постоянно смотрит логи и
метрики, замечает отклонения, **сам проводит первичную диагностику** и
показывает дежурному разбор: что случилось, где, на что похоже из уже
известного, куда смотреть дальше.

Агент **не чинит**. Починка — работа SRE. Агент сокращает время до обнаружения
и время до понимания.

### Чего агент не делает на первом этапе

- не выполняет команды на прод-хостах и не ходит по SSH;
- не меняет конфигурации, не перезапускает сервисы, не крутит ручки;
- не заменяет алертинг: у существующего мониторинга своя роль, агент рядом,
  а не вместо.

## 2. Действующие лица

| Лицо | Что делает | Что получает |
| :--- | :--- | :--- |
| **Дежурный SRE / DevOps** | читает разбор, выполняет заявки на диагностику, оценивает находки, дописывает root cause | канал диагностики и подсказку, куда смотреть |
| **Автор скиллов** (тот же SRE) | пишет скиллы анализа и заметки базы знаний | способ передать агенту свой опыт без программиста |
| **Руководитель** | читает недельный отчёт | картина здоровья системы на понятном языке |
| **Агент** | наблюдает, подозревает, расследует, пишет отчёты и черновики знаний | — |

## 3. Глоссарий

Термины обязательны к употреблению в коде, интерфейсе и разговоре. Одно
понятие — одно слово.

| Термин | Значение |
| :--- | :--- |
| **Наблюдение** (observation) | Числовой факт с горизонта: счётчик, значение метрики, их ряд по окнам. Берётся из коннектора, не интерпретируется |
| **Отклонение** (deviation) | Наблюдение, вышедшее за пороги детектора. Решение числовое и воспроизводимое |
| **Подозрение** (suspicion) | Отклонение, которое дешёвый отсев моделью счёл достойным разбора. Решение модельное и недетерминированное |
| **Расследование** (investigation) | Ограниченный по шагам сбор данных вокруг подозрения плюс разбор моделью. Даёт версию причины и рекомендацию |
| **Инцидент** (incident) | Долгоживущая сущность: сгруппированные подозрения об одной беде, все расследования по ним, заявки и отчёты. Единственное, к чему применимо «время до обнаружения» |
| **Заявка** (request) | Просьба агента к человеку снять диагностику, которую агент снять не может. Возвращается выводом в карточку |
| **Скилл** (skill) | Markdown-файл: когда применять, какие запросы снять, на что смотреть. Пишет человек, читает агент |
| **Заметка** (note) | Единица базы знаний: известная ошибка, разобранная авария, приём диагностики. Markdown в git |
| **Черновик** (draft) | Заметка, написанная агентом и ждущая приёмки дежурным |
| **Горизонт** (horizon) | Один из четырёх уровней анализа: 5 минут, 15 минут, час, сутки |
| **Коннектор** (connector) | Источник наблюдений: VictoriaLogs, VictoriaMetrics, дальше — прочие |
| **Отчёт** (report) | Документ для человека: по инциденту, по горизонту, недельный для руководителя |

## 4. Конвейер

```
коннекторы → наблюдения → [детектор] → отклонения → [отсев моделью] → подозрения
                                                                          ↓
                            инцидент ← группировка ←  [расследование] ←──┘
                               ↓                            ↑ ↓
                            отчёты                  база знаний, заявки
```

Три решателя стоят по возрастанию цены: детектор считает числа и стоит
доли секунды, отсев спрашивает модель одним коротким промптом, расследование
тратит минуты инференса. Дорогое включается только там, где дешёвое уже
сказало «смотри сюда» — см. [ADR-0001](adr/0001-two-contours.md).

### 4.1 Наблюдение и детектор

Детектор работает на числах и ничего не знает про модель. Требования:
робастность к собственным выбросам, объяснимость решения («счётчик 91 против
медианы 4.5»), настраиваемые пороги на горизонт.

### 4.2 Отсев

Один короткий промпт: «вот отклонение и его числа, стоит ли разбираться?».
Отсекает регулярный шум, который порогами не описать (ночная выгрузка,
известный болтливый сервис). Ответ по схеме: да/нет и одна фраза почему.

### 4.3 Расследование

Ведёт скилл: он задаёт первое досье. Дальше модель может запросить добор
данных из фиксированного меню, не более K шагов — [ADR-0002](adr/0002-bounded-tools.md).
В расследование входит поиск похожего в базе знаний.

Итог расследования: версия причины, уверенность, рекомендация «куда смотреть»,
при нехватке данных — заявка человеку.

### 4.4 Инцидент

Подозрения об одной беде группируются в инцидент. Инцидент живёт, пока
приходят подтверждения, и закрывается тишиной или человеком. К нему крепятся
расследования, заявки, оценки дежурного и итоговый отчёт —
[ADR-0010](adr/0010-incident-aggregate.md).

## 5. Горизонты

У каждого горизонта свой вопрос, свой набор скиллов и свой отчёт —
[ADR-0006](adr/0006-four-horizons.md).

| Горизонт | Вопрос | Что ищет |
| :--- | :--- | :--- |
| **5 минут** | что горит прямо сейчас | резкие всплески ошибок, отказы, обвал метрик |
| **15 минут** | это развивается или прошло | подтверждение, скорость роста, охват соседних сервисов |
| **час** | что тихо деградирует | утечки памяти, заполнение дисков, рост латентности, накопление ретраев |
| **сутки** | что повторяется | темы дня, возвращающиеся инциденты, сводка для дежурной смены |

## 6. Скиллы

Markdown с фронтматтером — [ADR-0003](adr/0003-skills-as-markdown.md).
Запросы пишутся на родном языке источника с пометкой коннектора —
[ADR-0005](adr/0005-native-queries.md).

Набросок формы (уточняется при реализации первого скилла):

```markdown
---
name: всплеск-ошибок-сервиса
horizon: 5m
when: отклонение по счётчику ошибок любого потока
collect:
  - vl: '_time:[{window}) {stream} | stats by (_msg_prefix) count()'
  - vm: 'rate(http_requests_total{job="{service}"}[5m])'
---

Сравни всплеск ошибок с нагрузкой. Если ошибки выросли, а запросы нет —
проблема внутри сервиса. Если выросло и то и другое — смотри на источник
нагрузки выше по цепочке.
```

## 7. База знаний

Markdown в git, хранение по образцу llm-wiki. Поиск полнотекстовый по тексту
и тегам — [ADR-0008](adr/0008-full-text-knowledge-search.md). Агент пишет
только черновики, в базу их переводит дежурный —
[ADR-0009](adr/0009-drafts-before-knowledge.md).

Виды заметок: известная ошибка (сигнатура → смысл → что делать), разбор
аварии (что было, причина, как чинили), приём диагностики (как смотреть).

## 8. Коннекторы

Общий трейт, набор собирается фичами под конкретную систему —
[ADR-0004](adr/0004-connectors-as-features.md). На первом этапе:
VictoriaLogs и VictoriaMetrics. Дальше — Zabbix, Jira и прочее.

Коннектор отвечает за: перечисление сущностей (потоки, серии), снятие ряда
по окнам, выборку сырых записей, выполнение произвольного родного запроса.

## 9. Отчёты

| Отчёт | Когда | Для кого |
| :--- | :--- | :--- |
| По инциденту | при закрытии инцидента | дежурный, разбор полётов |
| По горизонту | по расписанию горизонта, если есть о чём | дежурный |
| Недельный | раз в неделю | руководитель |

Отчёт — markdown-файл в git плюс страница на вебе. Отправка в мессенджеры —
следующий этап, формат к ней уже готов.

## 10. Приёмка

Считаем на живых данных, не на синтетике.

| Критерий | Цель | Как меряем |
| :--- | :--- | :--- |
| Время до обнаружения | **TBD** (вопрос открыт) | от первого наблюдения с отклонением до заведения инцидента |
| Доля ложных подозрений | не выше 30% на второй месяц | оценки дежурного в карточке |
| Полнота | ни один инцидент, замеченный людьми, не пропущен агентом | сверка с журналом дежурств |
| Недельный отчёт | выходит без ручной правки | факт |
| Нагрузка на стенд | скан горизонта 5м укладывается в минуту | замер |

## 11. Открытые вопросы

1. Целевое время до обнаружения — конкретное число.
2. Масштаб: сколько сервисов и потоков, объём логов в сутки, число серий метрик.
3. Первая система под внедрение.
4. Состав недельного отчёта для руководителя.
5. Где живёт репозиторий и репозиторий базы знаний.
