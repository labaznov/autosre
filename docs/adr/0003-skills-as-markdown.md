# ADR-0003: Скилл — markdown с фронтматтером

Статус: принято 14.08.2026

## Контекст

Скиллы анализа должны писать SRE, а не разработчики агента: смысл затеи в том,
чтобы опыт дежурного попадал в систему без релиза. Значит форма скилла обязана
быть доступна человеку, который уверенно пишет LogsQL, но не пишет на Rust.

## Решение

Скилл — файл markdown. Фронтматтер задаёт машинную часть: имя, горизонт,
условие применения, список запросов первого досье. Тело — инструкция модели
на русском: на что смотреть, как отличить одно от другого, что считать нормой.

Скиллы лежат в git рядом с базой знаний, подхватываются с диска без пересборки
и перезапуска.

## Следствия

- Ревью скилла — обычный pull request; история изменений бесплатна.
- Нужна валидация при загрузке: битый фронтматтер не должен ронять агента,
  скилл просто не применяется, а в журнал уходит одна строка почему.
- Форма скилла становится публичным интерфейсом: менять её потом дорого,
  поэтому первую версию проверяем на трёх-четырёх настоящих скиллах, а не на
  одном придуманном.
- Тело скилла попадает в промпт как есть — длина тела влияет на бюджет токенов.

## Альтернативы

- **Строгий YAML.** Проверяем схемой и предсказуем, но выразить «на что смотреть
  глазами» негде, а это половина ценности скилла.
- **Плагины WASM или Rust.** Максимум возможностей и скорости, но автор скилла
  снова упирается в разработчика — цель не достигается.
