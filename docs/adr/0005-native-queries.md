# ADR-0005: Скиллы пишут родные запросы источника

Статус: принято 14.08.2026

## Контекст

Скилл задаёт запросы, а источники разные: LogsQL, PromQL, дальше API Zabbix.
Либо скилл пишет на родном языке источника, либо мы вводим свой язык и
транслируем.

## Решение

В фронтматтере скилла — родной запрос с пометкой коннектора: `vl:` для
LogsQL, `vm:` для PromQL. Агент подставляет в запрос параметры окна и потока и
отдаёт его коннектору как есть.

## Следствия

- Полная выразительность источника доступна автору скилла с первого дня.
- Запрос проверяется копипастой в веб-морду Victoria — это резко сокращает цикл
  отладки скилла.
- Скилл привязан к стеку: при смене стека скиллы переписываются. Переносимость
  сознательно принесена в жертву.
- Подстановка параметров в текст запроса требует внимания к экранированию:
  значение потока приходит из данных, а не от человека, но правило «собираем
  запрос только в одном месте» обязано соблюдаться.

## Альтернативы

- **Свой язык запросов с трансляцией.** Полная переносимость, но транслятор в
  LogsQL и PromQL — самостоятельный продукт со своим сроком и своими багами.
- **Именованные запросы коннектора.** Скилл ссылается на `ошибки_по_сервисам`,
  реализация внутри коннектора. Переносимо, но каждый новый вопрос дежурного
  упирается в правку кода — противоречит ADR-0003.
