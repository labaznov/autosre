# ADR-0012: Состояние в SQLite, знания и отчёты в git

Статус: принято 14.08.2026

## Контекст

Агент хранит разное по природе: числовые наблюдения и состояние инцидентов —
машинные данные с частой записью; заметки, скиллы и отчёты — документы, которые
люди читают, правят и обсуждают.

## Решение

- **SQLite** — наблюдения, отклонения, подозрения, инциденты, расследования,
  заявки, оценки дежурного.
- **Markdown в git** — база знаний, скиллы, отчёты.

## Следствия

- Знания и отчёты живут без агента: их можно читать, грепать и править, даже
  когда агент лежит. Для базы знаний это принципиально.
- История правок и ревью достаются от git бесплатно — это же механизм приёмки
  черновиков (ADR-0009).
- Два хранилища — две процедуры бэкапа и возможность рассинхрона: инцидент
  ссылается на отчёт-файл, файл могут удалить. Ссылки обязаны переживать
  отсутствие файла.
- Агенту нужен доступ на запись в рабочую копию репозитория и умение делать
  коммит.

## Альтернативы

- **Всё в SQLite.** Один бэкап и никакого рассинхрона, но база знаний
  перестаёт быть llm-wiki и теряет ревью через git.
- **PostgreSQL с самого начала.** Запас на рост и несколько инстансов агента,
  но это новая инфраструктурная зависимость под нагрузку, которой пока нет.
