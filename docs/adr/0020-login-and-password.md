# ADR-0020: Вход по логину и паролю, без ролей

Статус: принято 14.08.2026

## Контекст

Веб-морда показывает содержимое прод-логов: адреса, имена сервисов, куски
сообщений с данными. Открывать её в сеть без входа нельзя. При этом полноценная
модель доступов — отдельная задача, и она отложена сознательно.

## Решение

Вход по логину и паролю. Учётные записи перечислены в конфигурации: имя и хеш
пароля (argon2). Сессия — подписанная кука с ограниченным сроком.

Ролей нет: вошедший может всё. Машинные вызовы (проверка здоровья, выгрузка
отчётов) идут по отдельному токену, а не по учётке человека.

## Следствия

- **Учёток несколько, а не одна.** Одна общая учётка сэкономила бы полчаса
  работы и обесценила бы авторство: приглушения
  ([ADR-0019](0019-muting-instead-of-per-service-thresholds.md)) и приёмки
  черновиков ([ADR-0009](0009-drafts-before-knowledge.md)) подписываются именем,
  и «дежурный» вместо имени сделает эту подпись бессмысленной.
- Пароль не хранится и не логируется в открытом виде нигде, включая журнал
  запросов. Это же относится к куке сессии.
- Ролей нет — значит любой вошедший может приглушить сервис или закрыть
  инцидент. Пока круг пользователей — дежурная смена, это приемлемо; как только
  появится кто-то, кому нужен только просмотр, понадобится модель доступов.
- HTTPS не входит в задачу агента и делается на входе (реверс-прокси). Пароль,
  ходящий по голому HTTP, — дыра, и это надо написать в инструкции по
  развёртыванию прямым текстом.

## Альтернативы

- **Без входа.** Так было в пилоте, и это годится для стенда, но не для
  продукта с прод-логами на экране.
- **Единая учётка на смену.** Проще, но убивает авторство действий, на котором
  держится приёмка черновиков и разбор приглушений.
- **Сразу модель доступов с ролями.** Правильно в конце, дорого сейчас, и её
  форма станет понятна только после первых недель работы.
