# ADR-0008: Полнотекстовый поиск по базе знаний

Статус: принято 14.08.2026

## Контекст

Расследование ищет в базе знаний похожий случай. Заметок со временем станут
сотни; в промпт они не помещаются. Варианты отбора: словарный поиск, векторный,
их гибрид, либо выбор моделью по оглавлению.

## Решение

Полнотекстовый поиск (BM25) по телу заметки и тегам фронтматтера, плюс переходы
по ссылкам между заметками. Запрос строится из сигнатуры ошибки, имени сервиса
и ключевых слов подозрения.

## Следствия

- Сигнатуры ошибок — редкие токены (`ECONNRESET`, `no space left`), по ним
  словарный поиск работает точно и без обучения.
- Попадание объяснимо: видно, по каким словам нашлась заметка. Это важно, когда
  дежурный не доверяет агенту и проверяет его выводы.
- Перефразировки не ловятся: «диск кончился» не найдёт `no space left`. Лечится
  тегами и синонимами во фронтматтере заметки, то есть дисциплиной автора.
- Индекс надо перестраивать при изменении файлов; на сотнях заметок это дёшево.
- Векторный поиск можно добавить позже вторым источником кандидатов, не ломая
  устройство.

## Альтернативы

- **Векторный поиск.** Ловит перефразировки, но требует эмбеддера на том же
  GPU, индекса и его инвалидации, а объяснить попадание сложнее.
- **Гибрид.** Лучшая полнота, но два индекса и ранжирование между ними — цена,
  не оправданная на старте.
- **Модель читает оглавление.** Работает на десятке заметок и разваливается на
  трёхстах.
