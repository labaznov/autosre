# ADR-0028: Бандл со статическим бинарём под systemd

Статус: принято 08.09.2026. Заменяет [ADR-0023](0023-deploy-with-downtime.md)
в части способа выкладки; обновление с остановкой и требование к миграциям
остаются в силе.

## Контекст

Агента будет ставить и сопровождать один человек, на сервере без интернета.
Роль Ansible из ADR-0023 копировала исходники на хост и собирала образ там:
нужны Docker, сеть до crates.io, две коллекции Ansible и git до репозитория
знаний. На сервере без сети это не работает вовсе.

Довод ADR-0023 против systemd — «сборка под целевую систему ложится на
выкладку, а зависимости — на хост» — устарел: бинарь собирается статически под
musl, весит около четырнадцати мегабайт и не зависит ни от одной библиотеки
хоста. Единственная внешняя программа, которую он зовёт, — `git` для коммита
принятых черновиков, и без него агент работает, только не коммитит.

## Решение

**Артефакт — тарбол**, собираемый там, где есть интернет, и переносимый одним
файлом:

```
autosre-<версия>-linux-x86_64/
  autosre            статический бинарь, LTO, strip
  autosre.toml       образец настроек с пояснением каждого поля
  autosre.env        образец секретов: три переменные
  autosre.service    юнит systemd
  install.sh         пользователь, каталоги, бинарь, юнит
  knowledge/         стартовая база знаний: скиллы, заметки, пустые drafts и reports
  README.md          установка на одну страницу
```

Рядом лежит `SHA256SUMS`. Сборка — задача CI на тег `v*`, тарбол
прикладывается к Release. Тег обязан совпадать с версией в `Cargo.toml`:
проверка в той же задаче.

**Установка**: распаковать, `./install.sh`, вписать секреты в
`/etc/autosre/autosre.env` и адреса в `/etc/autosre/autosre.toml`,
`systemctl start autosre`. Без Docker, без Ansible, без сети.

**Обновление**: распаковать новый тарбол, `./install.sh`. Скрипт кладёт новый
бинарь, а прежний оставляет рядом как `autosre.prev`, и перезапускает службу.
Откат — вернуть `autosre.prev` на место и перезапустить. Требование ADR-0023 к
миграциям — каждый шаг оставляет базу пригодной для предыдущей версии —
остаётся условием отката.

**Паника роняет процесс.** Профиль release собирается с `panic = "abort"`, а
юнит — с `Restart=always`. Фоновый цикл, упавший с паникой, раньше умирал
молча при живом процессе и зелёном здоровье; теперь падает всё, systemd
поднимает, состояние переживает перезапуск
([ADR-0021](0021-state-survives-restart.md)). Это проще супервизии задач и
честнее тихой смерти.

**Docker остаётся вариантом, не основой.** `Dockerfile` собирает тот же
бинарь; кому нужен контейнер, тот его соберёт. Роль Ansible удаляется:
инструментов должно быть столько, сколько сопровождающий может помнить.

## Следствия

- На сервере не нужно ничего, кроме systemd и, по желанию, `git`.
- Сборка идёт только в CI и только на тег: версия бинаря однозначна, и на
  вопрос «что у нас стоит» отвечает `autosre --version`.
- Один uid для процесса и данных, без согласования номеров между образом и
  ролью: пользователя заводит `install.sh`.
- Журнал — в `journalctl -u autosre`, без драйверов и ротации на стороне.
- Комплект модели в бандл не входит: стенд с моделью остаётся, агент ходит по
  адресу. Появится нужда — это отдельный комплект и отдельное решение.
- Тарбол несёт весь репозиторий знаний в стартовом виде; на месте он
  становится рабочей копией, и `git init` в нём — дело оператора.

## Альтернативы

- **Оставить роль Ansible, ужав до копирования бандла.** Ещё один инструмент
  ради одного `rsync`; при уходе тех, кто знал Ansible, роль становится
  обузой.
- **Образ Docker через `docker save`/`docker load`.** Работает без сети, но
  требует Docker на хосте и согласования uid между образом и каталогами;
  ради одного статического бинаря это лишний слой.
- **Пакет `.deb`/`.rpm`.** Правильнее для дистрибутивов, но привязывает к
  одному из них и требует своей сборочной обвязки; тарбол с `install.sh`
  ставится на любой Linux с systemd.
