# Задачи

Состав и порядок — [`PLAN.md`](PLAN.md). Здесь каждый шаг разрезан на задачи,
которые можно взять и закрыть по отдельности.

Каждая задача — тонкий вертикальный срез: проходит все слои, от источника до
наблюдаемого результата, и проверяется сама по себе. Задача, после которой
систему нельзя запустить, разрезана неправильно.

**AFK** — делается и вливается без участия человека. **HITL** — требует
доступа, решения или живых данных.

Термины в тексте — из [`SPEC.md` §3](SPEC.md), имена — из [`NAMES.md`](NAMES.md).

## Первый срез — сделан

### 1. Скелет: конфигурация, здоровье, свои метрики — **сделано**

**Тип:** AFK · **Зависит от:** —

Бинарь поднимается, читает TOML, отказывается стартовать без секретов, отвечает
на проверку здоровья и отдаёт свои метрики.

Готово, когда:

- [x] `autosre` читает файл TOML: адреса источников, горизонты, пороги, сроки;
- [x] отсутствие `AUTOSRE_MODEL_KEY` или `AUTOSRE_SESSION_KEY` останавливает
      старт с сообщением, называющим переменную;
- [x] неизвестное поле конфигурации — предупреждение в журнале, некорректное
      значение — остановка;
- [x] `GET /api/health` отвечает состоянием и версией;
- [x] `GET /metrics` отдаёт метрики в формате Prometheus;
- [x] `cargo test` и `cargo clippy --all-targets` чисты.

**Сделано иначе.** Вместо «возраста последнего бакета» публикуется момент
последнего бакета — `autosre_last_bucket_timestamp_seconds`, и до первого снятия
метрики нет вовсе. Возраст считает тот, кто настраивает алерт: `time()` минус
момент. Так принято в Prometheus и так не приходится выдумывать значение для
случая «бакетов ещё не было». Наполняется метрика в задаче 2.

**Проверено вживую:** старт без ключа останавливается с именем переменной;
неизвестная настройка даёт строку в журнале и не мешает работе; горизонтов
поднято три из четырёх описанных — пятиминутный выключен.

Опоры: [ADR-0025](adr/0025-config-file-and-secrets.md),
[ADR-0024](adr/0024-agent-under-watch.md).

### 2. Бакеты логов: от источника до строки в базе — **сделано**

**Тип:** AFK · **Зависит от:** 1

Коннектор VictoriaLogs снимает минутные бакеты по всем потокам одним запросом и
складывает их в базу. Собственные потоки агента исключаются в самом запросе.

Готово, когда:

- [x] один запрос в минуту приносит счётчики всех потоков за минуту;
- [x] число запросов к источнику не растёт с числом сервисов — проверено на
      пятидесяти потоках;
- [x] потоки из `self_streams` не попадают в ряд — проверено запросом, а не
      фильтрацией после;
- [x] шаблон ошибок обёрнут скобками: фильтр времени применяется ко всей
      OR-цепочке;
- [x] повторный запуск за ту же минуту не удваивает счётчики;
- [x] отказ источника не роняет агента: минута остаётся дырой, следующая
      снимается;
- [x] тесты идут против поддельного источника на эфемерном порту.

**Добавлено сверх критериев.** Живая проверка вскрыла случай, которого не было
в списке: источник с разъехавшимися часами вернул минуту, которую агент не
запрашивал. Такой бакет лёг бы в минуту, не отмеченную снятой, — значение есть,
а по отметкам это дыра. Теперь бакеты вне промежутка отбрасываются со строкой в
журнале.

**Проверено на живом источнике.** В лаборатории (`testlab/`) агент снял за
минуту ровно те же счётчики по потокам, что показывает прямой запрос к
`VictoriaLogs`.

**Появились крейты:** `autosre-domain` (минута, промежуток, поток, бакет),
`autosre-source` (трейт источника), `autosre-logs` (коннектор `VictoriaLogs`),
`autosre-store` (ряд наблюдений).

Опоры: [ADR-0013](adr/0013-minute-buckets.md), [ADR-0004](adr/0004-connectors-as-features.md),
[SPEC §1.1](SPEC.md).

### 3. Дозапрос дыр и свёртка ряда — **сделано**

**Тип:** AFK · **Зависит от:** 2

Старт восстанавливает пропущенное за время простоя. Раз в сутки минутные бакеты
сворачиваются в часовые, просроченное удаляется.

Готово, когда:

- [x] после остановки на десять минут старт закрывает дыру в ряду;
- [x] глубина дозапроса ограничена настройкой (`collector.backfill`) и не
      пытается восстановить месяц;
- [x] свёртка не теряет сумм: сумма часового бакета равна сумме его минутных;
- [x] удаление просроченного идёт по срокам из конфигурации;
- [x] свёртка не мешает снятию бакетов: она идёт по часу за транзакцию и
      уступает очередь между часами.

**Проверено на лаборатории.** Стёр отметки за десять минут — агент при старте
увидел одиннадцать дыр, закрыл их **одним** запросом (подряд идущие минуты
собираются в промежуток), разрывов в ряду не осталось. Свёртка на живых данных
дала 14 / 60 / 211 по часам — ровно те же суммы, что дают минутные бакеты.

**Появилось сверх критериев.** Признак свёртки у бакета: счётчик ошибок за час
складывается, занятая память — усредняется. Без него часовой ряд метрик был бы
бессмыслицей, а это задача 8. Заодно завёл механизм изменения схемы: шаги в
`user_version`, каждый оставляет базу пригодной для предыдущей версии агента —
без этого откат из ADR-0023 не работает.

Опоры: [ADR-0021](adr/0021-state-survives-restart.md), [ADR-0022](adr/0022-retention.md).

### 4. Детектор по логам — **сделано**

**Тип:** AFK · **Зависит от:** 2

Горизонт 15 минут поверх накопленного ряда: сумма последних пятнадцати бакетов
против своей истории. Вышедшее за пороги записывается отклонением с весом.

Готово, когда:

- [x] базовая линия считается по медиане и медианному отклонению, а не по
      среднему и сигме;
- [x] один выброс в истории не поднимает порог настолько, чтобы следующий такой
      же не сработал;
- [x] ровный ряд не даёт срабатываний;
- [x] решение объяснимо числами: счётчик, базовая линия, оценка;
- [x] вес считается и записывается вместе с отклонением;
- [x] пороги берутся из конфигурации, на горизонт.

**Лаборатория окупилась в первый же прогон.** С двумя часами истории детектор
нашёл «отклонения» у трёх живых сервисов с базовой линией ноль: пустые окна он
считал нулями, а «данных не было» и «ошибок не было» — разные вещи. На проде
это дало бы залп ложных срабатываний после каждого запуска и каждого простоя.

Исправлено: агент считает, сколько минут каждого окна он **действительно
снимал**. Окно, снятое меньше чем на 80%, в базовую линию не идёт; пока
известна меньше половины истории, горизонт молчит вовсе.

**Прогон после починки:** шесть часов истории, ровно одно отклонение —
`victorialogs`, 48 ошибок за окно против обычного нуля. Источник за те же
четыре минуты показывает 12+12+12+12 = 48. Болтливые сервисы промолчали.

**Мелочь, которая всплыла бы в карточке.** Бесконечная оценка (ошибок раньше не
было вовсе) хранилась предельным числом и показалась бы дежурному как
«оценка 1,8e308». Теперь в базе пусто, а читается как бесконечность.

Опоры: [SPEC §4.1](SPEC.md), [ADR-0018](adr/0018-investigation-queue.md).

### 5. Сигнатуры и инциденты — **сделано**

**Тип:** AFK · **Зависит от:** 4

Из выборки строк считается сигнатура ошибки. Отклонения группируются в инциденты
по паре «сервис плюс сигнатура»; инцидент живёт, пока приходят подтверждения.

Готово, когда:

- [x] сигнатура маскирует числа, адреса, пути, идентификаторы и длинные
      шестнадцатеричные;
- [x] сообщения, отличающиеся только числами, дают одну сигнатуру;
- [x] повторное отклонение той же пары не заводит второй инцидент, а продлевает
      первый;
- [x] инцидент закрывается тишиной по сроку из конфигурации;
- [x] инциденты, начавшиеся в одном окне, получают связь;
- [x] время открытия инцидента позволяет посчитать время до обнаружения.

**Проверено на лаборатории:** шторм `orders-api` завёл инцидент с сигнатурой
`ERROR upstream <addr> timed out after <n>s` — ровно шаблон генератора с
замаскированными адресом и секундами.

**Порядок шагов, а не только их состав.** Сперва образцы и сигнатура, потом
ключ, и только потом всё остальное. Пилот ходил в модель первым делом, а
дедупликацию проверял по полю, которое сама модель и заполняла.

**Трейт источника подрос на один метод** — выборка живых записей. У метрик их
нет по природе, поэтому по умолчанию пусто, а не «не поддерживается»:
отсутствие образцов — обычное дело, а не отказ.

Опоры: [ADR-0017](adr/0017-narrow-grouping.md), [ADR-0010](adr/0010-incident-aggregate.md).

### 8. Метрики: второй коннектор и второе правило — **сделано**

**Тип:** AFK · **Зависит от:** 4

VictoriaMetrics как источник: правила отбора серий, минутные бакеты, правило
детекции по уровню и направлению.

Готово, когда:

- [x] серии отбираются правилами из конфигурации, универсальный набор в поставке;
- [x] бакет метрики — среднее за минуту для уровней, приращение для счётчиков;
- [x] серии одного сервиса с разных инстансов сводятся к сервису;
- [x] ползучий рост находится там, где всплеска нет ни в одном окне;
- [x] **коннектор логов не потребовал правок** — граница трейта выдержала
      второй источник, дописан только метод выборки образцов, у метрик пустой;
- [x] список наблюдаемых серий виден на веб-морде — страница `/series`,
      сделана во втором срезе
      веб-морды, поведение агента от этого не зависит.

**Главное, что вскрыла лаборатория.** Робастная оценка не видит ровный тренд по
построению: базовая линия ползёт вместе с ним, разброс выходит соразмерным
шагу, и утечка памяти никогда не переходит порог. Правило для уровней
переписано: сравнение со старшей половиной истории плюс стойкость движения —
доля шагов в одну сторону. Скачок уровня ловится по-прежнему оценкой.

Заодно нашлось, что падающий уровень был невидим дважды: знак у бесконечной
оценки терялся, а вес считался только по превышению вверх. Для уровня обе
стороны равны — убывающий диск тревожит именно тем, что убывает.

**Проверено на живых данных:** диск 624 МБ против обычных 1163, память
`llama-server` 650 МБ против 489. Оба сценария генератора найдены.

Опоры: [ADR-0016](adr/0016-observed-metrics.md), [ADR-0004](adr/0004-connectors-as-features.md).

### 9. Отсев моделью — **сделано**

**Тип:** AFK · **Зависит от:** 5

Короткий запрос к модели: стоит ли разбираться. Отклонение становится
подозрением либо гасится.

Готово, когда:

- [x] форма ответа задана схемой, а не описана словами в промпте;
- [x] ответ разбирается строго, без выкусывания фигурных скобок регулярным
      выражением;
- [x] промпт укладывается в сотни токенов: в модель уходят сигнатуры со
      счётчиками, а не сырые строки;
- [x] **при недоступной модели инцидент всё равно заводится** — с пометкой
      «разбор отсева не состоялся»;
- [x] отказ модели виден в метриках агента;
- [x] тесты идут против поддельного `LiteLLM` на эфемерном порту.

**Отсеянное помечается, а не удаляется.** Иначе агент спрашивал бы модель об
одном и том же каждую минуту, а разобрать потом, что он гасил, было бы нечем.

**В лаборатории появилась поддельная модель** с предсказуемым правилом: первое
появление сигнатуры проходит дальше, повторы гасятся. Прогон подтвердил весь
конвейер — отклонение, отсев, инцидент, погашенный повтор.

**Мелочи, всплывшие на прогоне.** Метрика без метки сервиса называлась целым
селектором, а её сигнатура — «metrics на горизонте `<n>m`»: маскирование чисел
съело «15m». Теперь именем служит сама серия, а сигнатура собирается напрямую.

Опоры: [ADR-0001](adr/0001-two-contours.md), [ADR-0007](adr/0007-local-inference.md).

### 11. Скилл и расследование — **сделано**

**Тип:** AFK · **Зависит от:** 10

Скиллы читаются из рабочей копии репозитория знаний. Скилл задаёт первое досье,
модель может добрать данные ограниченное число раз, расследование заканчивается
выводом.

Готово, когда:

- [x] скиллы читаются с диска при старте, без пересборки;
- [x] битый фронтматтер не роняет агента: скилл не применяется, причина в журнале;

- [x] подстановки собираются в одном месте, значение потока очищается от того,
      чем можно закрыть строку и приписать своё;
- [x] добор ограничен числом шагов из конфигурации; меню закрытое — выдумать
      инструмент модель не может, схема не даст;
- [x] вывод содержит версию причины, уверенность и рекомендацию;
- [x] шаги расследования пишутся в базу по мере выполнения, а не в конце;
- [x] стартовые скиллы — из [`examples/knowledge/skills/`](../examples/knowledge/skills/),
      они же разбираются тестом.

**Перезагрузка скиллов на ходу отложена.** Сейчас они читаются при старте:
перезапуск агента стоит секунды (ADR-0023), а слежение за каталогом — отдельный
механизм со своими отказами. Появится, когда скиллы начнут править ежедневно.

**Проверено тестом целиком:** инцидент, подходящий скилл, первое досье, просьба
модели добрать данные, второй заход, вывод с уверенностью, два записанных шага.
Отдельно проверено, что просроченный инцидент доходит до дежурного без вывода и
**не тратит на себя модель**.

Опоры: [ADR-0002](adr/0002-bounded-tools.md), [ADR-0003](adr/0003-skills-as-markdown.md),
[KNOWLEDGE.md](KNOWLEDGE.md).

половину старого рассуждения с новым.

**Вопрос дежурному отложен** вместе с заявками (задача из следующего среза):
сейчас непонятное честно помечается на карточке, а спрашивать через веб-морду

Опоры: [ADR-0021](adr/0021-state-survives-restart.md).

      [`KNOWLEDGE.md`](KNOWLEDGE.md);

- [x] индекс полнотекстового поиска живёт в SQLite и строится при старте;

### 19. Черновик знания — **сделано**

только тогда заметка попадает в базу и в индекс.

Готово, когда:

- [x] черновик пишется в `drafts/` файлом с фронтматтером;
- [x] карточка показывает черновик с кнопками «принять» и «отклонить»;

### 20. Приглушение — **сделано**

**Тип:** AFK · **Зависит от:** 7

Пара «сервис плюс сигнатура» замолкает на срок. Подозрения продолжают
копиться тихо.

Готово, когда:

- [x] кнопка в карточке приглушает пару на срок, по умолчанию на неделю;
- [x] сохраняются кто, когда, до какого срока и почему;
- [x] приглушённое подозрение не заводит инцидент и не идёт в очередь;
- [x] приглушённые подозрения копятся и видны отдельным списком;
- [x] приглушение истекает само, снятие руками — кнопкой на `/mutes`;

**Сделано иначе.** Снятие видно на странице приглушений, а не в ленте: лента —
про инциденты, и строка «кто-то снял приглушение» в ней читалась бы как
инцидент.

### 21. Объединение и разделение инцидентов — **сделано**

**Тип:** AFK · **Зависит от:** 5

Дежурный чинит ошибку группировки в обе стороны, не трогая базу руками.

Готово, когда:

- [x] два инцидента объединяются в один, подтверждения и расследования
      переезжают;
- [x] инцидент разделяется по потоку: часть подтверждений уходит в новый;
- [x] объединённый помнит, из чего собран, и это видно в карточке;
- [x] время до обнаружения объединённого считается по самому раннему;
- [x] оценка дежурного переезжает вместе с инцидентом.

**Найдено после сдачи.** Разделение не держалось: новые подтверждения
выделенного потока снова прилипали к родителю, потому что привязка искала пару
без хвоста. Теперь выделенный инцидент имеет преимущество для своего потока, а
приглушение родителя накрывает выделенных потомков.

**Сделано иначе — по потоку, а не по сигнатуре.** Инцидент по построению
собирает пару «сервис плюс сигнатура» ([ADR-0017](adr/0017-narrow-grouping.md)),
двух сигнатур в нём не бывает, и делить по ней нечего. А вот потоков внутри
пары бывает несколько — разные хосты одного сервиса, — и вот там дежурному
действительно есть что выносить отдельно. Сигнатура выделенного уточняется
именем потока: пара должна остаться единственной среди открытых, иначе
группировка сольёт их обратно на следующей же минуте.

**Оценка переезжает, только если у принимающего её нет.** Чужая оценка не
отменяет своей: иначе объединение стало бы способом переписать чужой вердикт.

Влитый инцидент не удаляется и остаётся доступен по номеру — он несёт своё
время первого наблюдения, а на нём держится метрика времени до обнаружения. Из
ленты он убран: карточка у беды должна быть одна.

Опоры: [ADR-0010](adr/0010-incident-aggregate.md),
[ADR-0017](adr/0017-narrow-grouping.md).

сравнение с прошлой неделей, что по ним делали люди.

Готово, когда:

- [x] четыре части собираются из накопленного, без запросов к источнику;
- [x] «что делали люди» берётся из оценок, заявок и принятых черновиков —
      без этой части отчёт превращается в список жалоб;
- [x] отчёт читается человеком, не знающим устройства агента;
- [x] файл ложится в `reports/weekly/`.

**Не сделано.** Часовые бакеты до прошлого года в отчёт пока не заглядывают:
сравнение идёт с предыдущим таким же окном по минутным рядам. Для недели этого
достаточно, для «как год назад» — нет; это задача того среза, где появится
сравнение с прошлым сезоном.

Опоры: [SPEC §9](SPEC.md), [ADR-0022](adr/0022-retention.md).

### 26. Запросы скиллов исполняются — **сделано**

**Тип:** AFK · **Зависит от:** 11

Скилл объявляет `collect[].vl` и `collect[].vm`, а агент вместо них берёт
выборку строк по потоку. Текст запроса никуда не идёт.

Готово, когда:

- [x] у `Source` есть метод произвольного запроса на языке источника;
- [x] подстановки `{start}`, `{end}`, `{horizon}`, `{stream}`, `{service}`
      делаются в одном месте;
- [x] результат запроса виден шагом досье под именем `id`;
- [x] `collect` без `vl` и `vm` по-прежнему даёт выборку строк;
- [x] отказ одного запроса не срывает остальные.

**Сделано иначе.** Поле `tools` убрано из формата: оно читалось и ни на что не
влияло, а меню добора и так ограничено схемой ответа
([ADR-0002](adr/0002-bounded-tools.md)). Добавлены подстановки `{before}` и
`{metric}`: скиллы поставки уже пользовались ими под другими именами, и
запросы уходили в источник с фигурными скобками внутри.

Опоры: [ADR-0005](adr/0005-native-queries.md), [KNOWLEDGE §2](KNOWLEDGE.md).

### 29. Живучесть — **сделано**

**Тип:** AFK · **Зависит от:** 3

Дозапрос дыр только на старте, повторных попыток нет, здоровье всегда «ok».

Готово, когда:

- [x] дыры закрываются в цикле съёма, а не только при старте;
- [x] обрыв связи с источником и моделью повторяется с задержкой;
- [x] `/api/health` отвечает 503, когда последний бакет старше порога;
- [x] закрытие инцидентов не ждёт модели.

**Как устроено.** Дозапрос идёт каждый пятый круг съёма: когда источник
лежит, это семь напрасных запросов в пять минут, а не в минуту. Повторные
попытки — две сверх первой, после обрыва связи и кодов 429, 502–504; таймаут
не повторяется, думающей модели вторая попытка только добавит работы. Съём
вынесен в `Collector::round`, и его можно проверить без лаборатории.

Опоры: [ADR-0021](adr/0021-state-survives-restart.md), [ADR-0024](adr/0024-agent-under-watch.md).
