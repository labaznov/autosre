# Как участвовать

Проект ведётся спекой вперёд кода, и это не формальность: сперва решение и
запись о нём, потом код. Прежде чем браться, прочитайте
[`AGENTS.md`](AGENTS.md) — там порядок работы целиком.

## Правила, из-за которых пулл-реквест могут вернуть

**Термин из словаря имеет ровно одно имя в каждом слое.** Синоним в коде —
дефект, а не стилистика. Словарь — [`docs/NAMES.md`](docs/NAMES.md); прежде чем
назвать что-либо, загляните туда.

**Решение, которое трудно откатить, оформляется ADR.** Три условия сразу:
дорого передумать, будущий читатель спросит «почему так», и был настоящий
выбор из нескольких путей. Формат — по соседям в [`docs/adr/`](docs/adr/).

**Тест проверяет одно поведение одним утверждением.** Имя теста — предложение
о том, что проверяется. Никаких общих `setUp` и разделяемого состояния между
тестами: каждый готовит себе сам.

**Комментарий объясняет причину, а не пересказывает код.** Если из кода не
видно, почему сделано именно так, — это и есть повод для комментария.

## Перед отправкой

```bash
cargo test
cargo clippy --all-targets   # предупреждений быть не должно
cargo fmt
```

Тексты для человека — по-русски, имена в коде — латиницей. Сообщения об
ошибках и журнале: одно предложение с контекстом, без точки в конце.

## Что проверить руками

Изменения в конвейере проверяются на лаборатории, а не только тестами:

```bash
cd testlab && make up && make agent
```

Пять классов дефектов первого среза юнит-тесты не показали — их нашла
лаборатория. В тестах ряд всегда полный, история всегда есть, база всегда
своя; на живых данных ломается ровно это.
